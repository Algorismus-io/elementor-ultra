左は映像#2のヒーローとして実際に保存されているJSON——これまでエージェントが手書きしてきた対象そのものです。右はそれを生成する型付きコンポーネント。ミスはクライアントのサイト上ではなく、ビルド時に失敗します。

書き込みの前には必ずバックアップ。サーバー側のバリデータが不正なページを保存前に拒否します。ロールバックはいつでも可能。ハルシネーションを起こしたエージェントでも、サイトを壊すことはできません。

1200 · 1920 · 390

LIVE — 実際に走るループ(HOUSEMAITの実ログ)

そのFAILの行こそが肝心です。ゲートとは1200・1920・390px——デスクトップ、ワイド、モバイル——で走る自動pass/failチェック。エージェントは保存のたびに判定を受け取り、次の保存で自ら修正します。結果の確認はループに組み込まれていて、最後に思い出して回すスクリプトではありません。

04

スタック

5つのピース。全部使っても、ひとつだけでも。

01

コンパイラ + CLI

@algorismus/elementor-jsx

型付きJSX → ネイティブなElementor V4 JSON。ビルド、デプロイ、lint、メディア、インポート——そしてexjsx devのライブループ。

02

MCPサーバー

@algorismus/elementor-ultra-mcp

あらゆるMCPエージェント向けの90以上のツール:ページ構築、リファクタリング、デザインシステム管理、HTMLからElementorへの変換。

03

コンパニオンプラグイン

WordPressプラグイン · GPL

サイト側の正式なREST書き込み経路:サーバー側バリデーション、バックアップ、ロールバック、権限プローブ。

04

検証スタジオ

@algorismus/elementor-ultra-studio

デプロイのたびに:3つの幅でのpass/failチェック、サイトのヘルスチェック、レイアウト計測——Playwrightで自動化。

05

ローカルWORDPRESS

@algorismus/elementor-ultra-playground

ベイク済みスナップショットから、本物のWordPress + Elementorを数秒で。純粋なNodeのみ——Docker不要。

どこから始めるか迷ったら、コンパイラだけで十分—— npm i -D @algorismus/elementor-jsx。残りのピースは、必要になったときに加えればOK。
